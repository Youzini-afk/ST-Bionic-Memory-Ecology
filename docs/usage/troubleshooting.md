# 排障指南

**中文** · [English](troubleshooting.en.md)

本文从 [README](../../README.md) 拆出 ST-BME 常见用户问题与处理方式，便于按症状快速定位。

### 面板打不开

- 刷新 SillyTavern 页面。
- 确认扩展目录包含 `manifest.json`、`index.js`、`style.css`。
- 打开浏览器控制台搜索 `[ST-BME]`。
- 检查是否有其他扩展覆盖了左上角菜单结构。

### 后台没有产生新记忆

- 确认插件已启用。
- 确认当前聊天已有助手回复。
- 查看“总览 → 后台 Memory Steward”和“任务 → 持久化”。
- 检查 BME 专用模型是否已配置并通过连接测试；不会回退当前聊天模型或 DOA 模型。
- 首层或没有新事实时，Steward 可能明确返回 no-change，这不是失败。
- 如果账本正在加载/迁移或任务显示 deferred，先按面板错误修复配置或存储，再刷新聊天唤醒耐久 Inbox。

### 召回质量差

- 配置或修复 Embedding。
- 执行“重建向量”。
- 检查召回 Top-K、最终节点上限和 Recall Agent 是否开启。
- 可提交“整合/进化”后台请求，让 Steward 在完整语境中检查重复或冲突。
- 查看消息级召回卡片确认实际注入内容。

### 旧楼层隐藏后模型仍看到太多内容

- “限制聊天区渲染楼层”只减少前端加载，不负责节省 token。
- 真正控制上下文需要开启“隐藏旧楼层”。
- 设置修改后可点击“重新应用当前隐藏”。

### 手动记忆请求提示历史不完整

通常是因为开启了“限制聊天区渲染楼层”，当前前端只加载了最近 N 条。

处理方式：

1. 临时关闭“限制聊天区渲染楼层”，或把 N 调大到覆盖需要处理的范围。
2. 刷新当前聊天。
3. 再提交“重新提取/检查范围”请求。

这是保护机制，不代表图谱丢失。

### 节点看起来突然清空

- 先刷新页面。
- 如果刷新后恢复，通常是运行时状态暂时不一致，持久化图谱没有丢。
- 查看“总览 → 最近恢复”和“任务 → 持久化”。
- 不要立刻执行“重建图谱”，除非确认要从聊天记录重新生成全部记忆。

### 召回卡片不显示

- 确认目标楼层是用户消息。
- 空召回也应显示卡片；检查目标消息是否有 `message.extra.bme_recall`，以及状态是否为 `ready` 或 `empty`。
- 第三方主题需要保留 `#chat .mes` 消息节点和稳定楼层索引属性，例如 `mesid`、`data-mesid` 或 `data-message-id`。
- 打开调试日志后搜索 `[ST-BME] Recall Card UI`。

### reroll 提示耐久产物不可用

- BME 不会在 reroll 阶段重新运行召回或 ENA，也不会只凭消息缓存注入旧内容。
- 这通常表示父 user 楼层缺少 Recall / Planner Artifact，或该楼层、历史证据、聊天身份已经变化。
- 保留当前输入重新发送可建立一个新的 user 回合；如果是旧版数据，先完成一次性账本迁移后再生成新回合。

### 直连 Embedding 失败

- 检查 API 地址和模型名。
- 检查 Key。
- 检查浏览器 CORS。
- 默认优先使用直连外部 Embedding；若服务无法提供浏览器 CORS，再考虑宿主后端索引支持的模型。
